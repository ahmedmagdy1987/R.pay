## What was tested, in exactly three places

### 1 · The spine as the page progress rail
`_c/SpineRail.tsx` · a 4px fixed rail at the top of the document.

Not a progress bar tinted brass. It is **the same object compressed**: nine brass segments, each
opening with a node, and **the segment widths are the real machine counts** — Riyadh is the
widest because Riyadh has 18 machines. Progress travels along it as cyan, because "where you are
in the document" is live state and cyan means live.

Add two machines in Riyadh and this rail changes shape, exactly as the hero does.

Compositor path where supported (`animation-timeline: scroll(root block)`, zero JS per frame),
one shared rAF as fallback. No library.

**Honest verdict:** this inherits **the spine half** of the grammar — segments and nodes — but
not the peg, because a progress rail has nothing to hang. That is correct for its job, but it
means the rail alone would not identify the brand. It identifies it *in company*.

### 2 · The joint as a section divider
`_c/JointRule.tsx` · server component, zero JS, sits between the hero and the geofence section.

A section break is normally a 1px line — the single most generic element in web design. This one
is the grammar at rest: a **brass spine that breaks**, nodes opening each segment, and **one peg
hanging off it** — stem, JOINT, head. The head takes the colour of the section it introduces, so
the divider *states what is coming* rather than merely separating.

**Honest verdict:** the strongest of the three. It is unmistakably the same system, and it
replaced a plain hairline rather than being added on top of one — the radar section's old
`border-top` is gone. One device, not two.

### 3 · The peg as the mark
`public/brand/mark.svg` + 32/180/512 PNG, generated by `scripts/make-favicon.mjs`, wired into
route metadata.

Three pegs on a broken brass spine. Same atom: spine · socket · stem · JOINT · head. **One head
is graphite**, because seven of ninety-seven are offline and the mark tells the truth too.

**Honest verdict:** legible and clearly the same object from 24px up. **At 16px the joint closes
and it reads as a brass bar over three marks** — recognisable in company, weaker alone. If we
want 16px to hold, the fix is a dedicated single-peg variant at that size, not a redraw.

A caught error worth recording: the first mark put the spine break *through* the middle peg, so
that peg attached to nothing. In a grammar where the whole idea is that machines are *pegged to*
infrastructure, that is not a cosmetic slip. The break now always falls between pegs.

## The 1920px problem — fixed, and it was two bugs

You flagged the brass stem comb reading as texture rather than structure. Diagnosed rather than
guessed, and it was not one issue:

1. **The instrument was capped at the text column.** `.stage` was `max-width: 1320px`, so on a
   1920 screen the drawing rendered at 1176px with ~600px of unused width — small, and the stems
   thinned into hairlines. Now the **stage spans 1680px and the reading blocks stay capped at
   1320px**, so the instrument is 1536px. That is the hierarchy stated as layout: *the spine
   outranks the text column.*
2. **The sweep was stranded on screen.** `overflow: visible` on the SVG — needed for the breach
   label — also let the travelling light render outside the viewBox, so it parked at the left
   edge and never left. It now fades on its last frame rather than relying on geometry.

Both are visible in `shots/01-desktop-1920-ar.png`.

Brass was also promoted throughout: **spine 4.5, stem 1.5, machine head 2.5.** Infrastructure is
drawn heavier than any single node.

## My honest read of the sheet

**It is one language.** The divider and the mark are unmistakably the same system as the hero —
same break, same node, same joint, same colour law. Put the divider next to the horizon and no
one would ask whether they belong together.

**Where it thins, precisely:**

- **The rail carries the spine but not the peg.** Correct for its job, but it means one of the
  three repetitions is a partial inheritance rather than a full one. It works *as part of the
  set*; it would not carry the brand alone.
- **At 16px the mark loses the joint** — the one feature doing the identifying.

So: **three of four scales carry the full grammar; the rail carries half of it by design.** That
is a system, not a drawing. I would not claim more than that.

**What would falsify it later:** if the paper act (Daybreak) needs a different divider, or if a
data-less section has nothing to hang pegs from, the grammar will be exposed as hero-only. The
divider's `tone` prop already anticipates the first; the second is untested and is the real risk
in Milestone 2.

Per your instruction, Higgsfield is out. Worth stating plainly: **no generated asset has been
used in anything built so far.** Every mark in Milestones 1, 1.1 and 1.2 is SVG drawn in code —
the horizon, the rail, the divider, the mark. The only remaining bitmap on the route is the
existing `machine-arcade.webp` render in the geofence section, which predates this work.

Higgsfield appeared only as a *proposed* HIGH-VALUE item (three 320×180 sensor-feed loops) in
`01-PRODUCTION-SPEC.md` §12. That entry is now struck. If ambient footage is ever wanted, it
comes from a real camera or it does not ship.
